# 河洛行记 · 四日山水旅行相册

这是一个无需构建工具、可直接部署到 GitHub Pages 的旅行影集。视觉采用暖宣纸、墨绿、朱砂与鎏金配色。除白马寺、洛阳古墓博物馆、少林寺、龙门石窟、老君山、清明上河园六个目的地外，还设有“车窗手记 · 一路向中原”与最后一栏“杂项”。前者用于收藏坐火车启程途中拍摄的田野、站台与窗外风景；“杂项”用于保存不属于固定景点的随手拍、食物、沿途小景和其他零散回忆。两者都拥有独立卡片和单独筛选，不影响原本四天行程。

## 权限设计

- **访客：** 无需登录，打开网址即可浏览所有已上传照片和视频。
- **唯一管理员：** 账号名为 `admin`。只有该账号可以上传照片 / 视频、替换现有媒体、修改显示名称和说明、删除媒体。
- **密码：** 由 Supabase Auth 校验，不写在 `index.html`、SQL 或 GitHub 仓库中。
- **后端权限：** 数据库与 Storage 的 RLS 策略都限定管理员邮箱 `admin@luoyang-album.app`，不是单靠前端隐藏按钮。

> 本站用 GitHub Pages 做公开前端，用 Supabase 做共享数据和身份验证。云端配置未完成时，管理按钮保持关闭；必须完成云端配置才能让家人通过同一网址共享照片。

## 一、部署到 GitHub Pages

1. 解压下载的 ZIP 文件。
2. 在 GitHub 创建一个新仓库，将 `index.html`、`README.md` 和 `supabase-setup.sql` 上传到仓库根目录。
3. 打开仓库 **Settings → Pages**，在 **Build and deployment** 选择 `Deploy from a branch`，分支选择 `main`，目录选择 `/(root)`，保存。
4. 当前版本的 `index.html` 已预填你提供的 Supabase Project URL 与 Publishable key，上传后即可连接该项目；管理员账号和数据库权限仍需按下文完成配置。

## 二、配置共享相册与管理员账号

### 1. 创建 Supabase 项目

在 [Supabase](https://supabase.com/) 创建项目，然后打开项目的 **SQL Editor**，将本仓库中的 `supabase-setup.sql` 全部复制执行。现有相册升级只需先执行 `thumbnail-upgrade.sql`，不必重建项目。

该 SQL 会创建媒体数据表、公开读取的 Storage 存储桶，并将写入、替换、修改元数据和删除权限限制为单一管理员邮箱。请在你自己的 Supabase 项目中运行，避免与其他用途的数据表或策略混用。

### 2. 创建唯一管理员

1. 在 Supabase Dashboard 打开 **Authentication → Users**，手动添加一个用户。
2. 邮箱填写：`admin@luoyang-album.app`。
3. 密码栏填写你刚才指定的管理员密码，并在创建用户时启用“确认邮箱 / Auto Confirm User”（这个映射邮箱不用于收信）。密码只保存在 Supabase Auth 中，不会写入项目文件。
4. 在 **Authentication 设置**中关闭公开用户注册（Allow new users to sign up），不要给访客提供注册入口。

网页登录框中输入的用户名是 `admin`；网页会将它映射到上面的管理员邮箱，由 Supabase 验证密码。不要在网页代码或公开 README 里硬编码管理员密码，也不要在前端使用 `service_role` / secret key。

### 3. 填写前端配置

在 Supabase 项目的 API 设置中复制 **Project URL** 和 **anon / publishable key**。编辑 `index.html`，找到：

```js
window.ALBUM_CONFIG = {
  SUPABASE_URL: "",
  SUPABASE_ANON_KEY: "",
  BUCKET: "luoyang-travel-album",
  ADMIN_EMAIL: "admin@luoyang-album.app"
};
```

当前提供的部署包已将 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY` 填入为你提供的项目值。如果你使用此项目，通常不需要再修改这两项。已有部署先在 Supabase SQL Editor 执行 `thumbnail-upgrade.sql`，再将新版 `index.html` 覆盖上传到 GitHub，并等待 Pages 部署完成。

**只使用 anon / publishable key。绝对不要把 Supabase `service_role` 或 secret key 放到公开网页。** anon / publishable key 本身会公开，真正保护写入权限的是 SQL 中的 RLS 策略。

### 4. 使用方法

- 普通访客直接打开 GitHub Pages 网址，即可浏览全部公开影像，无需登录。
- 管理员点击右上角“管理员登录”，输入账号 `admin` 和在 Supabase 创建用户时设置的密码。
- 登录后，每个目的地、“车窗手记”及最后的“杂项”卡片会出现上传按钮；每张媒体上方会出现编辑、替换和删除操作。
- “编辑”可修改媒体显示名称和说明；“替换”可上传新的照片或视频替换原文件；“删除”会移除影像记录。
- 新增的“杂项”位于所有目的地卡片的最后，可单独筛选并用于存放不属于具体景点的照片或视频。
- 管理完成后点击“退出登录”。访客不需要登录，且不会看到任何管理操作。


### 5. 中文文件名说明

Supabase Storage 对对象路径中的部分非 ASCII 文件名可能返回 `Invalid key`。网页会自动将上传文件的**云端存储路径**转换为安全的英文、数字、下划线与扩展名；数据库中仍保留原始中文文件名用于网页显示，不需要用户手动重命名照片。

## 图片三层版本、渐进式预览与加载优化

- **三层图片版本：** 原图保存在 `storage_path`，用于用户主动查看/下载；`preview_path` 保存最长边约 1920 px 的高清预览图；`thumbnail_path` 保存最长边约 560 px 的相册缩略图。WebP 优先，浏览器不能编码 WebP 时回退 JPEG。原图不会因生成展示版本而被压缩或删除。
- **列表优先小图：** 每个地点默认只渲染最早上传的 6 段媒体；点“查看全部”才创建后续媒体节点。缩略图使用浏览器懒加载与异步解码，首张照片提高加载优先级，视频列表仅显示播放占位图。
- **点击照片渐进展示：** 弹窗先显示缩略图，然后并行加载高清预览图，加载完成后才替换，避免大图加载期间出现空白。弹窗提供独立的“查看原图 / 下载原图”入口，原图只在用户主动选择时请求。预览界面不显示存储文件名。
- **管理员 SDK 延迟加载：** 普通访客只通过轻量 Supabase REST 接口读取公开相册目录，不下载 Supabase Auth SDK。只有点击管理员登录时才加载认证 SDK。最近访问过的浏览器会先显示最多缓存 7 天的公开目录，再从云端刷新；缓存不包含密码或登录令牌。
- **自动验证现有路径：** 管理员登录后，网页会批量用轻量 `HEAD` 请求检查已有缩略图与高清预览图的对象路径。HTTP 明确返回不存在/不可访问时才标记为失效；网络超时或浏览器跨域错误视为“状态未知”，避免误删或无谓重生成。
- **可恢复的旧照片批处理：** 对缺失或已确认失效的展示版本，管理员页面自动逐张下载原图并生成缺失的版本；每张处理后更新数据库路径，再尝试清理旧展示文件。原图始终保留。处理中断后，刷新页面或下次管理员登录会重新检查并继续处理；清理旧文件失败不会导致新路径回滚。
- **新上传 / 替换：** 照片上传时会同时生成并保存缩略图与高清预览图；视频不进行图片转码。若某个展示版本上传失败，原图仍会保留，页面会提示后自动触发补齐流程。
- **缓存与旧图说明：** 新生成的展示对象使用一年缓存头并采用新路径更新，避免旧缓存继续指向坏图。旧照片只会在管理员批处理检查到路径缺失/失效时补齐；不能让原图凭空变小。点击“查看原图”或“下载原图”仍需传输完整文件，速度取决于原图大小和网络。
- **公开密钥：** Supabase `sb_publishable_*` 通过 `apikey` 请求头发送；不要把 `service_role` 或 secret key 写入公开网页。权限仍由数据库 RLS 和 Storage 策略控制。参阅 <https://supabase.com/docs/guides/getting-started/api-keys>。

### 已有项目升级步骤

1. 在 Supabase Dashboard 打开 **SQL Editor → New query**，执行本目录的 `thumbnail-upgrade.sql`。该脚本可重复运行，只添加 `thumbnail_path` 和 `preview_path` 两个字段并通知 PostgREST 刷新 schema；不要对已有项目重新运行完整初始化 SQL。
2. 将本目录新版 `index.html` 覆盖上传到 GitHub 仓库根目录并提交，等待 GitHub Pages 发布完成。
3. 打开网页后点击管理员登录。管理员认证 SDK 加载完成、相册目录读取成功后，系统会自动检查路径并逐张补齐缺失/失效的展示版本；无需手动点击按钮。
4. 批处理期间保持管理页面打开，浅绿色面板会显示检查与补齐进度。失败项会在下一次管理员登录或刷新后重新检查；若连续失败，请检查浏览器 Console、Storage 权限和原图是否可访问。
5. 普通访客不会触发路径检查或图片批处理，也不会加载 Supabase Auth SDK。

## 隐私说明

此配置的 Storage 桶为公开读取，因此所有上传的照片和视频均可通过公开 URL 访问。适合旅行纪念相册，不适合身份证件、家庭住址、票据等敏感文件。如果将来希望相册只对指定家庭成员可见，需要改为私有 bucket 与授权访问链接。

## 响应式排版与上传顺序（最新版）

- **电脑端：** 使用三列自适应卡片网格，桌面浏览时每一行卡片对齐；中等宽度设备自动切换为两列，避免瀑布流在宽屏上出现参差和大块空白。
- **手机端：** 保留单列景点卡片和每张卡片内三列照片缩略图；每个地点初始只渲染最早的 6 段媒体，点击“查看全部”再加载余下内容，减少首次请求量。
- **照片较多时：** 手机与电脑均默认显示最早上传的 6 段影像，更多内容可点击“查看全部”展开，避免初次加载大量照片。
- **上传顺序：** 云端查询和前端展示都按 `created_at` 升序排列，即最早上传的照片在前，后来上传的照片依次排在后面。编辑说明或替换文件不会改变该影像记录原有的上传顺序。

普通的纯前端样式修改通常只需覆盖 `index.html`。但本次三层图片升级新增了 `preview_path` 字段：如果尚未执行本次升级，请先按“已有项目升级步骤”执行 `thumbnail-upgrade.sql`，再上传新版网页。


## 手机端首次加载与弹窗体验优化

- **公开页面不加载登录 SDK**：普通访客只使用轻量 REST 目录接口；只有点击管理员登录入口时才加载 Supabase Auth SDK。
- **本机目录缓存**：浏览器缓存公开媒体目录最多 7 天，复访先显示缓存再更新数据；不缓存密码或管理员令牌。
- **列表按需渲染**：每个相册默认只创建最早上传的 6 段媒体，点击“查看全部”后再创建其余内容。缩略图 lazy-load + async decode，视频不预加载视频元数据。
- **三层图片**：新上传时保留原图，另生成 560px 缩略图与最长边 1920px 高清预览图。弹窗立即显示缩略图并并行获取高清预览，完成后平滑替换；只有点击“查看原图 / 下载原图”才传输完整原图。
- **旧照片**：管理员登录后自动检查已登记的缩略图和预览图路径是否能访问。只重生成缺失/明确失效的衍生图，不会反复处理可访问的展示版本，也不会删除原图。检查网络失败或 CORS 阻止 HEAD 时会视为状态未知，实际渲染遇到失败时再将该路径标记为失效。
- **缓存策略**：新展示图使用不同的新路径和一年缓存头，避免浏览器继续命中之前失效的 URL。视频仍保持原文件，不进行自动转码。


## 旧照片自动补齐说明

- 不需要再寻找或点击“生成缩略图”按钮。管理员登录后会自动启动一次路径检查与补齐任务。
- 系统检查缩略图与高清预览图是否真实可访问，不只看数据库字段是否为空。
- 任务按小批量验证路径，再逐张生成缺失版本；每张只重新生成缺失或失效的衍生图，尽量不重复下载原图。
- 页面关闭或网络中断后，下一次管理员登录会重新检查。处理成功后数据库指向新路径；原图仍保留。失败项会显示数量与下次重试提示。
